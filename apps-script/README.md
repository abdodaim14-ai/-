# تفعيل نظام طلبات التلاوات وتتبعها

رابط Web App الذي رُبط به الموقع حاليًا:
`https://script.google.com/macros/s/AKfycbyvE7yshdccLDJPiIP_-oiH7eLYidqPg-ruOQ4WTiPveULA7nsbv314-8M4T8K4MNYGFg/exec`

> هذا رابط تطبيق Google Apps Script المنشور (Web App)، وليس رابط فتح جدول Google Sheets نفسه. يجب أن يكون مشروع Apps Script مربوطًا بجدول التسجيلات الصحيح.

## خطوة التفعيل المطلوبة في Google Apps Script

1. افتح مشروع Apps Script المرتبط بجدول التسجيلات الذي يستقبل البيانات.
2. خذ نسخة احتياطية من الكود القديم قبل تغييره.
3. افتح `apps-script/Code.gs` في GitHub وانسخ الكود كاملًا إلى ملف `Code.gs` في مشروع Apps Script.
4. تأكد أن المشروع مربوط بنفس جدول البيانات القديم، وأن الأعمدة الأصلية A:J لم تتغير.
5. من **Deploy → Manage deployments** افتح نشر Web App الحالي واضغط تعديل (القلم)، ثم اختر **New version** واضغط **Deploy**. بهذه الطريقة يظل رابط النشر نفسه.
6. إعداد التشغيل: **Execute as: Me**، وإتاحة الوصول: **Anyone** أو **Anyone, even anonymous** حسب الخيارات الظاهرة؛ لأن صفحة التتبع عامة. لا تستخدم رابط `/dev`.
7. من قائمة الدوال في محرر Apps Script اختر `authorizeExternalRequests` ثم اضغط **Run** ووافق على صلاحيات الاتصال الخارجي (`UrlFetchApp`) عند ظهور شاشة التفويض. هذه الصلاحية مطلوبة للتحقق من جلسة Supabase داخل لوحة الإدارة.
8. وافق على صلاحيات Google Drive وGoogle Sheets عند ظهورها.
9. افتح رابط Web App نفسه في نافذة متصفح عادية. يجب أن يعرض JSON فيه `totalCount` و`latestReaders`، ثم اختبر البحث برقم طلب موجود.

## دورة الطلب

- التسجيل الجديد يضيف البيانات الأصلية إلى A:J ورقم الطلب إلى K، والحالة إلى L.
- لوحة الإدارة `admin.html` تعرض الطلبات، والصورة والتسجيل، وتسمح بالقبول أو الرفض.
- عند الرفض يجب كتابة سبب واضح؛ يظهر السبب لصاحب الطلب في `track.html`، ويُرسل إشعار داخل المنصة للحساب الذي أرسل الطلب وهو مسجل الدخول.
- يستطيع صاحب الطلب إعادة التقديم من صفحة التتبع باستخدام رقم الطلب ورقم الهاتف المسجل، واستبدال الصورة أو التسجيل أو الاثنين.
- بعد إعادة التقديم ترجع الحالة تلقائيًا إلى «إعادة التقديم - قيد المراجعة».

## أعمدة التتبع

- A:J: البيانات الأصلية كما هي.
- K: رقم الطلب.
- L: حالة الطلب.
- M: ملاحظات داخلية للإدارة، لا تظهر للمتقدم.
- N: آخر تحديث.
- O: عدد مرات إعادة التقديم.
- P: معرّف حساب صاحب الطلب لإرسال إشعار خاص عند قبول الطلب أو رفضه.
- Q: سبب الرفض أو الملاحظة الظاهرة للمتقدم في صفحة التتبع.
- R: سجل مراحل الطلب بصيغة JSON.
- S: موعد النشر المحدد.
- T: رابط التلاوة المنشورة.
- U: ملاحظة عامة تظهر للمتقدم.
الطلبات القديمة التي لا تحتوي على معرّف حساب في P ستظل قابلة للتتبع، لكن لن يصلها إشعار خاص تلقائي.

## لوحة الإدارة والأمان

قائمة الطلبات في لوحة الإدارة لا تُعرض إلا بعد التحقق من جلسة Supabase وصلاحية `admin_check_access`. لا تضع مفتاحًا سريًا أو Service Role Key في ملفات الموقع. مفتاح Supabase المنشور المستخدم هنا هو المفتاح العام فقط.

## الصور والتسجيلات

يحفظ السكربت نوع MIME الأصلي للصورة والتسجيل بدل إجبار كل الملفات على JPEG وMP3؛ وهذا يمنع عدم تطابق الامتداد ونوع الملف، خصوصًا مع تسجيلات M4A وصور PNG وWebP. لا يعتبر رفع الملف ناجحًا إلا بعد تأكيد Google Drive أن المشاركة عبر الرابط مفعّلة. إذا كانت سياسة حساب Google تمنع المشاركة العامة، سيظهر خطأ واضح بدل حفظ رابط لا يستطيع الزوار فتحه.

## الخطوط والهوية

رفع ملف الخط من لوحة الإدارة يحفظ بيانات الخط في إعدادات المظهر، ويقرأه ملف `site-theme.js` لتطبيقه على الصفحات الأساسية. الأنواع المدعومة: TTF وOTF وWOFF وWOFF2، بحد أقصى 450 كيلوبايت.

**مهم:** تعديل GitHub لا يحدّث Apps Script تلقائيًا. لا بد من نسخ الكود ونشر إصدار جديد كما في الخطوات أعلاه. لا تحذف جدول البيانات أو صفوف التسجيلات القديمة.


## نظام مراحل تنفيذ التلاوة الجديد

بعد نسخ الكود المحدّث من `apps-script/Code.gs` إلى مشروع Apps Script ونشر إصدار جديد:

- تعرض بطاقة الطلب في لوحة الإدارة صورة القارئ ومشغّل التسجيل مباشرة داخل الصفحة.
- اختر المرحلة من القائمة، وأضف موعد النشر أو رابط التلاوة المنشورة ورسالة للقارئ، ثم اضغط حفظ تحديث الطلب.
- كل تغيير يُسجل بتاريخ ووقت في سجل المراحل بالعمود R، وموعد النشر في S، ورابط النشر في T، والرسالة العامة في U.
- صفحة التتبع تعرض صورة القارئ والتسجيل ومراحل التنفيذ وسجلها الزمني وموعد النشر ورابط التلاوة بعد نشرها.
- عند كل تحديث تُرسل إشعارات داخل المنصة للحساب المرتبط بالطلب (إذا كان القارئ قد قدم الطلب وهو مسجل الدخول).

**تنبيه خصوصية مهم:** لتشغيل الصور والتسجيلات داخل الموقع، يضبط الكود صلاحية ملفات Drive على «أي شخص لديه الرابط يمكنه العرض». كما يطبق ذلك عند عرض الملفات القديمة من صفحة الإدارة أو التتبع. لا تستخدم هذا الأسلوب لملفات لا تريد إتاحة رابطها لمن يمتلكه.

**النشر:** تحديث GitHub لا يحدّث Google Apps Script تلقائيًا. انسخ الملف المحدّث إلى مشروع Apps Script، ثم من Deploy → Manage deployments عدّل النشر الحالي واختر New version ثم Deploy مع الاحتفاظ بنفس رابط Web App.
